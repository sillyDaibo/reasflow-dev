## 先读这些结论

1. **按原 Judge 分，B 的方法/设置综合分略高，结果分较低。** 每篇等权的 Midloop 平均为 A **74.22%**、B **75.13%**，B−A **+0.91 个百分点**；Bigloop 为 A **46.16%**、B **40.73%**，B−A **−5.44 个百分点**。16 篇中 Bigloop 的 B 胜/负/平为 **4/10/2**。这只是该配置、该批次、完成子集的描述，不能直接解释为整个 ReasFlow 产品的因果效果。
2. **通过评分门槛不等于完整证明论文。** Midloop 通过为 A **7/16**、B **8/16**；两层同时通过各 **2/16**，均为 RSA（1811.03761）和 stochastic-gradient SCAFFOLD（2503.07594）。这些任务仍有失败条目及量规解释边界，不能写成“所有论文主张都已证实”。
3. **复现失败与评测失真同时存在。** 实验覆盖不足、算法递推偏差和结果排序反转有直接证据；但也发现旧运行结果污染、量规公式写反、严格数值容差和不稳定的“近似/曲线趋势”解释。低分必须拆到具体 claim，不能全部归因于 Agent 不会复现。
4. **B 实际发挥的是部分工作流能力。** 运行时配置、技能访问和真实调用要分别检查。已存轨迹中没有观察到 A/B 的 `spawn_agent` 调用；注册了子 Agent 不代表本轮执行了子 Agent 协作。本报告仅根据公开消息、命令、工具事件和产物还原可观察的复现策略，不将其等同于模型内部思考。
5. **资源隔离不能按设计文档宣称。** 原003有14对A/B的启动记录均为CPU集合`0-15`，其余2对记录为互不重叠的集合。这是配置/启动证据，不是每个子进程全过程的实际affinity测量；资源竞争尤其限制墙钟时间的解释。
6. **汇总口径会改变印象。** ManPQN 一篇包含 361/634 个 Bigloop 条目、494/959 的 Bigloop 总权重，占分别 **56.94%/51.51%**。全部条目直接加权会得到 A **22.00%**、B **18.67%**，远低于每篇等权结果。评价“跨论文能力”应主要看每篇等权，同时保留原始条目账。
