## 论文动机与核心主张

DPG-RR 解决随时间变化的多智能体网络上的非光滑有限和凸优化。随机有放回 SGD 每轮可能遗漏样本，而每样本调用昂贵 prox 又增加成本；该法每个 epoch 对局部样本重新排列，连续做光滑梯度更新，再用逐渐增加的多步共识映射混合节点，最后每 epoch 只做一次非光滑正则的 prox。理论证明节点达成共识，并以 O(1/T+1/√T) 逼近最优解的邻域；这是带假设和邻域项的收敛结论，不应写成任意常步长下精确求解。对 L1 正则 logistic，prox 就是 soft threshold。[摘要](/Users/zanehuang/work/OptiRepro/datasets/benchmarks/cpu30_v1/input/2111.03820/data/paper.md:488) [方法成本与范围](/Users/zanehuang/work/OptiRepro/datasets/benchmarks/cpu30_v1/input/2111.03820/data/paper.md:1134)

## 逐项评分解读与问题定位

源码显示非常实质的协议差别：A 对排列后的每个样本做一步 `w-=step_size*g`；B 默认 batch=800，使用 batch 平均梯度再乘 batch/n_local，故一个 epoch 仅有少数大 batch 更新，总有效梯度尺度接近一次全梯度步。这与逐样本 RR 的路径不同，也会淡化采样顺序影响；B 配置明确保留800，不能用“只是向量化加速”概括。`res-016` 两边均失败，B 的 RR/SG/IG曲线几乎重合与上述机制相符；因未做同协议消融，它是有证据支持的解释而非唯一已证根因。[A 逐样本更新](/Users/zanehuang/work/OptiRepro/reports/cpu30/analysis-2026-09-06/evidence/OptiRepro_cpu_2/agent_reproduction/runs/2111.03820/Codex原生-完整复现-Goal/第003次运行/workspace/src/algorithms.py:96) [B 批处理与缩放](/Users/zanehuang/work/OptiRepro/reports/cpu30/analysis-2026-09-06/evidence/OptiRepro_cpu_2/agent_reproduction/runs/2111.03820/ReasFlow实验Agent-完整复现-Goal/第003次运行/workspace/src/disprox_rr/algorithms.py:88) [B 消融配置](/Users/zanehuang/work/OptiRepro/reports/cpu30/analysis-2026-09-06/evidence/OptiRepro_cpu_2/agent_reproduction/runs/2111.03820/ReasFlow实验Agent-完整复现-Goal/第003次运行/workspace/results/formal/sampling_ablation_e200_s0-1-2/config.json:1)

共识排序也受基线实现影响。A固定图终点a9a DPG-RR≈1.73e-24、DSGD≈2.50e-26，因此 `res-001` 被罚；B 对应为0、1.2164，因此同项通过。A给DSGD/DGM也调用 epoch+1 次多步 `_mix`，B DSGD只做一次静态矩阵混合再加随机梯度；这不是相同基线下 Agent 精度差异。把1e-24与1e-26的舍入级残差严格排序，本身也缺乏数值意义。B共识实现还 `max(0,value)` 截断负舍入误差，报告的精确0不是无限精度共识证明。[A 基线共识增强](/Users/zanehuang/work/OptiRepro/reports/cpu30/analysis-2026-09-06/evidence/OptiRepro_cpu_2/agent_reproduction/runs/2111.03820/Codex原生-完整复现-Goal/第003次运行/workspace/src/algorithms.py:118) [B DSGD更新](/Users/zanehuang/work/OptiRepro/reports/cpu30/analysis-2026-09-06/evidence/OptiRepro_cpu_2/agent_reproduction/runs/2111.03820/ReasFlow实验Agent-完整复现-Goal/第003次运行/workspace/src/disprox_rr/algorithms.py:198) [B 截断共识量](/Users/zanehuang/work/OptiRepro/reports/cpu30/analysis-2026-09-06/evidence/OptiRepro_cpu_2/agent_reproduction/runs/2111.03820/ReasFlow实验Agent-完整复现-Goal/第003次运行/workspace/src/disprox_rr/algorithms.py:76)

时间是大环低分的另一来源。`res-004`至`res-011`八项逐字要求原表秒数，容差±0.1秒：A没有导出分方法计时（虽然 RunResult 有 elapsed_seconds字段），因此证据缺失；B确实导出，DPG-RR在a9a约3.345秒、w8a约17.053秒，因远快于原秒数照样失败。跨硬件、语言、数据处理方式用绝对秒数极窄容差，不可靠地测量复现质量。不过独立排序 `res-012` 的B失败有意义：本次 Prox-G仅1.302/4.577秒、NEXT1.251/5.143秒，DPG-RR实际更慢，且 batch算法与工作量差异需要一并解释。不能把“时间匹配失败”与“效率主张逆转”混为一谈。

最后，中环唯一失败 `alg-009` 把“arbitrarily initialize”理解为必须支持随机初始化；全1本来就是一个合法任意初值，且论文明确比较方法相同初始化。这是字面化误判。相反，中环没有充分识别 batch800对RR路径的改变、基线多步共识差异及不同方法按 epoch 比较的梯度预算不等。该篇最有价值的结论不是近满分中环，而是它展示了“公式部件齐全”与“经验比较可解释”之间的大差距。
