# Original-paper derivation basis

Source: the supplied arXiv:2501.09516v1 PDF, 37 pages. Only this PDF and the contract schema were read; no implementation, adapter, history or output was consulted. Formulae on PDF pages 7–9 were rendered and visually checked.

The contract tests ManPQN Algorithm 1 (PDF page 7) with the practical diagonal damped LBFGS update in Section 3.2. PDF page 4 Eqs. (2.1)–(2.2) define tangent projection and the Riemannian smooth gradient. Eqs. (3.1)–(3.2) on page 6 and (3.6)–(3.8) on page 8 give the convex proximal tangent subproblem and diagonal metric. Eqs. (3.9)–(3.10), pages 8–9, define damping and BFGS. Eq. (3.3), page 7, defines nonmonotone Armijo acceptance. Page 21 states the SVD retraction choice; for St(2,1) that polar retraction is normalization of X+V.

Both cases run three full updates on the curved manifold St(2,1), with nonzero l1 regularization, coupled nonidentity quadratic smooth terms, and specified initial unit vectors. At k=0, B=I follows Algorithm 1 exactly. At k>=1, memory one resets the base to delta I and retains the newest secant pair, using Riemannian gradients but Euclidean differences as instructed on page 8. The full B matrix is observed separately from the diagonal used by the tangent subproblem.

The first case rejects initial step sizes 1 and 1/2 before accepting 1/4, and later accepts a small objective increase using the nonmonotone history. The second case reaches a proximal l1 knot and activates damping at the next update (beta approximately 0.79787234), then takes a nonmonotone uphill step. Thus curvature, damping, nonsmooth branching, retraction and history-based acceptance all affect the trajectories. Initial identity is not propagated as a surrogate for BFGS.

The subproblem is solved exactly for this dimension. Write t=(-x2,x1), V=z*t. Its strictly convex objective is a*z + b*z^2/2 + mu*(|x1+z*t1|+|x2+z*t2|), where a=Euclidean gradient dot t and b=t^T diag(B)t. Enumerate the stationary point in every valid sign interval and both l1 knots. Then apply the original line search and retraction. This replaces only the internal numerical solver for the mathematically specified minimizer; it does not approximate or simplify away the ManPQN update.

`derive_contract.py` is a standalone standard-library-only derivation with 70-digit Decimal arithmetic and embedded paper identity. It reads no input files, asserts tangency and retracted feasibility at 1e-60, and rounds once to binary64 JSON. atol = 1e-9 and rtol = 1e-8 allow double-precision arithmetic, while the public inputs request an exact/sufficiently accurate small inner solve so solver residuals do not change the contract. Observation step j means outer k=j-1, with pre/post update timing explicit. The neutral initial damping-beta observation is explicitly marked as a no-pair sentinel.

Scope is finite ManPQN behavior with memory one and r=1. It does not verify the adaptive semismooth Newton solver's internal iterates, longer LBFGS history, multi-column Stiefel interactions, full experimental performance or convergence proofs. It uses the practical Eqs. (3.6)–(3.10), not the transported theoretical BFGS expression (3.5). This document is derivation evidence, not an independent paper review.

## Inner accuracy qualification

The analytical subproblem in Eqs. (3.1)/(3.6) is an argmin. The practical solver description on PDF pages 10–11 solves Eq. (3.19) with ASSN and refers elsewhere for detailed iteration policies; numerical settings on pages 20–21 impose a maximum of 100 inner iterations. The supplied text does not give a complete, uniquely specified ASSN residual/termination policy that would force every implementation to return the same finite direction. This contract therefore explicitly requests the exact-inner-solve specialization and tolerances stated in the public inputs. A permitted inexact solver can produce a legitimate different trajectory. Disagreement with these precise expected directions is only failure of this exact-solve experimental specialization, not by itself evidence of a general ManPQN algorithm error. The experiment does not derive or invent an inexact termination criterion from outside sources.

Verification: repeated execution reproduced contract bytes exactly; an independent 100-digit recomputation of the same paper-derived arithmetic agreed with the stored binary64 expected values within 4e-70 (only roundoff representations of exact zeros differed). Public cases were checked to contain neither private expected arrays nor derivations.
