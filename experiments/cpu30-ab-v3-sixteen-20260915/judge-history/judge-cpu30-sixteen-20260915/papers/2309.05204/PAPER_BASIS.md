# Original-paper basis and limited scope

Paper: arXiv:2309.05204v1, supplied PDF, 5 pages. Only this PDF and the contract schema were read. No implementation, previous evaluation, adapter or actual-run output was consulted. Key formulae were visually checked on PDF page 3.

The contract tests **nonaccelerated PIRL1-AM, Algorithm 1**, not the accelerated algorithm in the title. PDF page 2 Eq. (3) specifies the quadratic-penalty objective; Eq. (7) reweights by previous z; Eq. (12) and page 3 Algorithm 1 give signed componentwise thresholding using previous z in the denominator; Eq. (14) gives the coupled u linear solve. Each of two 3-pixel periodic instances runs three complete updates. A nonidentity circulant blur and nonzero cyclic finite difference couple all coordinates. The cases exercise positive, negative and thresholded-to-zero values and update the weights at every iteration. Public observations specify both pre-update gradient/thresholds and post-update z/u/objective.

There are two material source ambiguities. Eq. (11) uses bar-z in the threshold denominator while Eq. (12) and Algorithm 1 use z. This contract explicitly chooses the final Algorithm 1 pseudocode and Eq. (12), consistent with Eq. (7). More seriously, page 3 Eqs. (16)–(18) and Algorithm 2 compute extrapolation y, but the printed closed-form z and u formulas never specify how y feeds the next update; the text also states z_k = gradient u_k despite z being a separate split variable. The supplied paper therefore does not uniquely specify the operational accelerated recursion. No inference from any implementation is used to fill that gap. Passing these cases is evidence for the nonaccelerated subalgorithm only and cannot establish correctness of the paper's main claimed acceleration, convergence speed, image PSNR/SSIM or full reproduction.

All algorithm inputs, epsilon, initial z/u, boundary convention, coefficient values and observation timing are public. epsilon = 0.01 is a small positive fixed regularizer chosen for stable separation of threshold branches. p = 0.1 and L = 1 match Algorithm 1. No random generation, early stop, intensity clipping or parameter continuation occurs.

`derive_contract.py` is an independent standard-library-only 70-decimal-digit derivation with embedded paper hash. It takes no input files and prints the private contract. Powers use Decimal exponentiation and the u step uses a direct 3-by-3 elimination. Stored numbers are rounded once to JSON binary64. atol = 1e-10, rtol = 1e-9 allow ordinary double-precision implementation arithmetic while remaining much smaller than the activated update effects. JSON schema validation and public-field stripping were performed through the provided paper_contract module. This document is a derivation basis, not an independent review.

Verification: repeated execution reproduced contract bytes exactly; an independent 100-digit recomputation of the same paper-derived arithmetic agreed with the stored binary64 expected values within 4e-70 (only roundoff representations of exact zeros differed). Public cases were checked to contain neither private expected arrays nor derivations.
